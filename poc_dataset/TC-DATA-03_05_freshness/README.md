# TC-DATA-03/04/05 — Freshness / 변경 반영 / 삭제 반영

원본 gaia_dataset은 손대지 않고, 이 폴더의 문서만 별도 "living source"로 사용합니다.

## TC-DATA-03 (Continuous Indexing Freshness) / TC-DATA-04 (변경 반영)
1. `living_policy_v1_90days.docx` 를 보호 대상 소스(NAS 등)에 올리고 백업 → Dataset에 인덱싱.
2. "현재 스냅샷 보존 기간은?" 질의 → **90일** 확인.
3. 소스 위치의 파일을 `living_policy_v2_60days.docx` 내용으로 **교체**(파일명은 동일하게
   유지하거나, 실제 운영처럼 같은 파일을 열어 90일→60일로 직접 수정해도 무방).
4. 신규 백업 스냅샷 생성 → Last Indexed 갱신 대기.
5. 동일 질문 재질의 → **60일**로 바뀌었는지, 백업 완료~답변 반영까지 걸린 시간(Data
   Freshness) 측정.
6. 구 값(90일)이 여전히 답변에 섞여 나오면 실패.

## TC-DATA-05 (삭제 반영)
1. `deletion_candidate_falcon7.docx` 를 동일 소스에 함께 업로드 후 인덱싱.
2. "임시 프로젝트 코드명은 무엇입니까?" → **Falcon-7** 확인.
3. 해당 파일을 소스에서 삭제 → 재인덱싱.
4. 동일 질문 재질의 → 더 이상 검색/답변에 노출되지 않아야 함 (무응답 또는 정보 없음
   처리가 정상).

## 왜 별도 문서를 쓰는가
gaia_dataset(DART 공시)은 원본이라 실제로 값을 고치거나 지우면 안 됩니다. 위 문서들은
이번 목적으로 새로 합성한 것이라 자유롭게 수정·삭제해도 되는 "소모용" 픽스처입니다.
