================================================================================
1  현재 구조 요약
================================================================================

  /data/richard/
  |-- data/                        원본 데이터 (git 아님, 163GB)
  |   |-- gaia_dataset/             DART 공시 문서 (103GB, 275개사)
  |   `-- gaia_web_dataset/         웹 수집 문서 (60GB)
  |-- gaia_scenario/                PoC 50개 TC 시나리오 (git, GitHub 연결됨)
  |   `-- poc_dataset/
  |       |-- paths_config.py       GAIA_DATASET_DIR / GAIA_WEB_DATASET_DIR 정의
  |       `-- (TC별 fixture, 전부 저장소 안에 복사되어 있어 원본 없이도 읽힘)
  `-- gaia_eval/                    RAGAS 자동 평가 파이프라인 (git, GitHub 연결됨)
      |-- gaia_dataset/config.py    GAIA_DATASET_DIR 정의 (DART 공시용)
      `-- gaia_web_dataset/config.py DATASET_DIR(=GAIA_WEB_DATASET_DIR) 정의 (웹 문서용)

  gaia_scenario와 gaia_eval 둘 다 원본 데이터를 복제하지 않고 절대경로로
  가리키기만 합니다. 즉 "코드"와 "대용량 원본 데이터"는 완전히 분리되어 있고,
  이전 방법도 서로 다릅니다 — 코드는 git clone, 데이터는 별도 전송.

================================================================================
2  git clone만 하면 되는 것
================================================================================

  git clone https://github.com/woohwan/gaia-scenario.git
  git clone https://github.com/woohwan/gaia_eval.git

  - gaia_scenario: 저장소 전체 약 126MB (poc_dataset의 fixture 데이터 포함, 전부
    git에 커밋되어 있어 clone만 하면 바로 읽을 수 있음)
  - gaia_eval: 저장소 전체 약 16MB (코드 + 과거 실행 결과 output/eval json 포함)

  둘 다 새 머신에 네트워크로 다운로드되는 부분이라 별도 파일 전송이 필요 없습니다.

================================================================================
3  git 밖에서 별도로 옮겨야 하는 것 (대용량 원본 데이터)
================================================================================

  gaia_dataset(103GB), gaia_web_dataset(60GB)는 git에 없고 앞으로도 넣으면 안
  됩니다(GitHub 100MB/파일 제한 + 저장소 비대화). rsync, tar+scp, NAS 공유,
  오브젝트 스토리지(S3 등) 중 편한 방법으로 별도 전송하세요.

  참고: 이 머신의 /data/richard/data/ 밑에 이미 예전에 쓰던 tar 아카이브가
  남아있습니다 (gaia_dataset.tar ~110GB, gaia_web_dataset_0807.tar ~63GB).
  같은 방식(tar로 묶어서 scp/rsync 후 새 머신에서 풀기)을 재사용해도 됩니다.

  예시 (rsync, 권장 — 재개 가능):
    rsync -avP --info=progress2 \
      /data/richard/data/gaia_dataset/ \
      user@new-host:/원하는/경로/gaia_dataset/
    rsync -avP --info=progress2 \
      /data/richard/data/gaia_web_dataset/ \
      user@new-host:/원하는/경로/gaia_web_dataset/

  새 머신에서 데이터를 다른 절대경로에 두기로 했다면(예: /mnt/data/... 등)
  5절의 GAIA_DATASET_DIR / GAIA_WEB_DATASET_DIR 환경변수로 반드시 오버라이드
  하세요 — 안 하면 두 저장소 모두 옛 기본값(/data/richard/data/...)을 그대로
  찾다가 실패합니다.

================================================================================
4  git에는 있지만 .gitignore로 빠지는 것 (새로 만들어야 함)
================================================================================

  두 저장소 모두 .gitignore에 아래가 있어 clone해도 안 딸려 옵니다:

    __pycache__/
    *.pyc
    .venv/
    .env
    **/.env

  그래서 새 머신에서 직접 만들어야 하는 것:

  - conda 환경(gaia-eval): gaia_eval 저장소 루트에서 ./setup_env.sh 재실행
    (임베딩 모델 다운로드까지 이 단계에서 검증함, README.txt 2절 참고)
  - .env 파일(Docker로 gaia_dataset 실행 시): gaia_eval/gaia_dataset/.env.example을
    복사해 .env로 만들고 API 키 채우기
      cp .env.example .env && vi .env
  - gaia_web_dataset은 Docker 구성이 없어 .env 대신 셸 export로 직접 설정
    (README.txt 5절 참고)

================================================================================
5  새 머신에서 설정해야 하는 환경 변수
================================================================================

  5-1. 데이터 경로 (새 머신에 데이터를 다른 위치에 둔 경우에만 필요)

    변수                   적용 대상                              conda/로컬 실행  Docker 실행
    ---------------------  --------------------------------------  ---------------  ------------------
    GAIA_DATASET_DIR       gaia_scenario/paths_config.py           O                X (아래 참고)
                           gaia_eval/gaia_dataset/config.py        O                X
    GAIA_WEB_DATASET_DIR   gaia_scenario/paths_config.py           O                O (web은 Docker 없음)
                           gaia_eval/gaia_web_dataset/config.py    O                O
    HOST_GAIA_DATASET_DIR  gaia_eval/gaia_dataset/docker-compose.yml (호스트 경로)   -                O

    주의: gaia_eval/gaia_dataset를 Docker로 돌릴 때는 GAIA_DATASET_DIR이 아니라
    HOST_GAIA_DATASET_DIR을 오버라이드해야 합니다. docker-compose.yml이 호스트의
    ${HOST_GAIA_DATASET_DIR}을 컨테이너 내부 /data/gaia_dataset로 마운트하고,
    컨테이너 안에서는 GAIA_DATASET_DIR=/data/gaia_dataset로 고정되어 있기
    때문입니다(docker-compose.yml 12,27행). GAIA_DATASET_DIR을 host에서
    export해봤자 컨테이너에는 영향 없습니다.

    예시 (데이터를 /mnt/data/에 옮긴 경우):
      export GAIA_DATASET_DIR=/mnt/data/gaia_dataset
      export GAIA_WEB_DATASET_DIR=/mnt/data/gaia_web_dataset
      export HOST_GAIA_DATASET_DIR=/mnt/data/gaia_dataset   # docker 쓸 때만

  5-2. LLM / 임베딩 API 키 (gaia_eval 실행 시 필요, 새로 발급/설정)

    ANTHROPIC_API_KEY       LLM_PROVIDER=claude(기본)일 때 필요
    OPENAI_API_KEY          LLM_PROVIDER=chatgpt 또는 EMBEDDING_PROVIDER=openai일 때 필요
    HUGGING_FACE_HUB_TOKEN  선택 — 로컬 임베딩 모델 다운로드 rate limit 방지용

  5-3. Cohesity Gaia 클러스터 접속 정보 (GAIA API 평가 단계에서만 필요)

    COHESITY_CLUSTER_URL     예: https://<helios-fqdn>
    COHESITY_API_KEY         Helios > Settings > Access Management > API Keys
    COHESITY_DATASET_NAME    평가 대상 Gaia Dataset 이름

    이 3개는 "어느 머신에서 스크립트를 돌리는가"와 무관하게 Cohesity 클러스터
    자체의 접속 정보입니다. 새 머신이 그 클러스터에 네트워크로 도달 가능한지
    (방화벽/VPN 등)도 함께 확인하세요.

================================================================================
6  이전 후 검증 절차
================================================================================

  1) 데이터 무결성 확인 (새 머신에서)
       find /새경로/gaia_dataset -mindepth 1 -maxdepth 1 -type d | wc -l   # 275
       du -sh /새경로/gaia_dataset            # 약 103G(약 110GB 소수점 표기)
       find /새경로/gaia_web_dataset -type f | wc -l                      # 39199
       du -sh /새경로/gaia_web_dataset        # 약 60G

  2) gaia_scenario 경로 설정 확인
       cd gaia_scenario/poc_dataset
       python3 -c "
       import paths_config as p
       print(p.GAIA_DATASET_DIR, p.GAIA_DATASET_DIR.exists())
       print(p.GAIA_WEB_DATASET_DIR, p.GAIA_WEB_DATASET_DIR.exists())
       "
       # 둘 다 True가 나와야 함. False면 5-1의 환경변수를 확인.

  3) gaia_eval 경로 설정 확인
       cd gaia_eval
       python3 -c "
       import sys; sys.path.insert(0, 'gaia_dataset')
       import config; print(config.GAIA_DATASET_DIR, config.GAIA_DATASET_DIR.exists())
       "
       python3 -c "
       import sys; sys.path.insert(0, 'gaia_web_dataset')
       import config; print(config.DATASET_DIR, config.DATASET_DIR.exists())
       "

  4) conda 환경 + API 키 확인
       conda activate gaia-eval
       cd gaia_dataset && ./run.sh --step sample --company 삼성전자 --sample-size 3
       # 3개 문서 샘플링이 에러 없이 끝나면 데이터 경로 + LLM 키 모두 정상

  5) (선택) Cohesity Gaia 연결 확인 — gaia_eval/README.txt 3절 curl 예시 참고

================================================================================
7  알려진 한계 / 이전 후에도 자동으로 안 따라오는 것
================================================================================

  - gaia_eval의 output/eval 밑 과거 실행 결과 JSON(qa_pairs_*.json,
    sampled_documents_*.json 등, 총 21개)의 file_path 필드는 "절대경로"로
    박혀 있습니다(이번에 /data/richard/data/...로 갱신은 했지만, 상대경로가
    아니라서 또 다른 머신으로 가서 데이터 위치가 달라지면 다시 깨집니다).
    gaia_scenario 쪽 fixture(TC-FUNC/_index.json, TC-DATA-01 QA 샘플)는 이미
    상대경로로 고쳐서 이 문제가 없지만, gaia_eval의 이 결과 파일들은 "과거 실행
    기록"이라 성격이 달라 손대지 않았습니다. 필요하면 해당 --step을 재실행해서
    새로 생성하면 새 경로로 다시 만들어집니다.
  - gaia_eval/gaia_dataset/TEST_SCENARIOS.md는 여전히 예전 프로젝트
    (cohesity-poc/gaia_ragas, qdrant-rag 서비스)를 기준으로 쓰여 있어 지금
    구조와 안 맞습니다. 이번 경로 정리에서 의도적으로 제외했습니다(별도 확인 필요).
  - Mailbox/OneDrive Dataset(TC-FUNC-02, TC-DATA-08)은 파일 기반 데이터가
    아니라 M365 테넌트 백업이라, 새 머신으로 데이터를 옮기는 것과 무관하게
    Cohesity 쪽에서 별도로 연결해야 합니다.
  - Cohesity Gaia에 이미 등록된 Dataset(gaia_scenario/poc_dataset/
    DATASET_REGISTRATION/README.md 참고)은 소스 절대경로를 기준으로 만들어져
    있으므로, NAS 소스 경로 자체가 바뀌면(단순 클라이언트 머신 이전이 아니라
    백업 대상 자체가 이동한 경우) Cohesity 쪽 소스/Dataset도 재설정해야 합니다.
    이건 이 문서가 다루는 "클라이언트 머신 이전"과는 별개의 작업입니다.
