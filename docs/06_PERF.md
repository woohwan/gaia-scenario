**사전조건**: Indexing이 완료된 Dataset, 부하가 없는 상태(다른 사용자 활동 없음).

### 데이터 준비
- `finance-core` Dataset 재사용(01_FUNC.md).

### 테스트 수행 절차
1. 부하가 없는 시간대에 `finance-core` Dataset에서 [QA_finance_core.md](QA_finance_core.md)

3. 10회 이상의 측정값으로 P50(중앙값), P95(상위 5% 지연)를 산출.

## TC-PERF-02 — 동시 사용자 부하 테스트 `[P1]`

> **API 제외에 따른 절차 조정**: 원본은 k6/Locust 등으로 API를 동시 호출하는 방식을
> 전제로 하지만, 이번 문서 세트에서는 API가 없으므로 **여러 명의 실제(또는 원격
> 지원) 사용자가 각자 브라우저에서 Gaia AI Assistant에 동시 로그인해 질의**하는
> 수동 부하 시뮬레이션으로 대체합니다. 정밀한 처리량/오류율 수치가 필요하면 API
> 제공 후 k6/Locust로 재측정을 권장합니다.

### 데이터 준비
- `finance-core` Dataset, [QA_finance_core.md](QA_finance_core.md)에서 5~10개 질문 선정.
- 1/5/10/20명 규모의 테스트 참여자(또는 여러 브라우저 프로필/시크릿 창으로 동일
  사용자 세션을 병렬로 열어 흉내낼 수도 있으나, 실제 동시 사용자에 가까운 결과를
  얻으려면 서로 다른 계정/브라우저 세션을 권장).

### 테스트 수행 절차
1. 1명이 동일 질문셋을 질의하며 기준(baseline) 응답 시간 측정.
2. 5명이 동시에 각자 브라우저에서 동일 질문셋을 동시에(신호에 맞춰) 입력, 각자 응답
   시간과 오류(타임아웃, 오류 메시지 등) 여부 기록.
3. 10명, 20명 규모로 반복.
4. 규모별 응답 지연 증가 추이와 오류 발생 건수를 집계.

### 예상 결과 / 합격 기준
- 동시 사용자 증가에 따른 응답 지연 증가가 완만하고, 오류율이 급증하지 않음.
- 목표 동시 사용자 수에서 성공률 ≥ 99%(수동 측정 기준), 응답 지연이 목표 SLA 이내.

### 결과 기록
| 동시 사용자 수 | 평균 응답 시간 | 오류 발생 건수 | 성공률 |
|---|---|---|---|
| 1 / 5 / 10 / 20 | | | |

## TC-PERF-07 — 대용량 동시 인덱싱 중 질의 응답 안정성 `[P3]`

**사전조건**: 신규 대용량 Dataset Indexing이 진행 중인 상태.

### 데이터 준비
- `perf-100gb`(또는 `perf-200gb`)와 `finance-core`가 **동시에** 등록되어 있어야 합니다
  ([00_COMMON_SETUP.md](00_COMMON_SETUP.md) 0.4절 비고 참고).

### 테스트 수행 절차
1. `perf-100gb`(또는 200gb) Dataset의 신규 Indexing을 시작.
2. Indexing이 진행되는 동안 `finance-core`(기존에 이미 인덱싱 완료된 Dataset)에
   TC-PERF-01과 동일한 질문셋으로 정상 질의를 수행하며 응답 시간을 측정.
3. Indexing이 진행 중이지 않은 평상시(TC-PERF-01 결과)와 응답 시간을 비교.

### 예상 결과 / 합격 기준
- Indexing 부하가 기존 질의 서비스 응답성에 심각한 영향을 주지 않음.
- Indexing 중 질의 응답시간 저하가 평상시 대비 목표 범위(예: +30% 이내).
